THE 4 FACTS THAT SOLVE EVERYTHING
1. Random variable (RV): a numerical measure of the outcome of a probability experiment — a number whose value is determined by chance.
2. Discrete vs. continuous: ask "Do I COUNT it or MEASURE it?" Counted with gaps (0, 1, 2, …) → discrete. Measured on a scale where any decimal is possible (rain, time, weight) → continuous.
3. Legal probability distribution — 2 rules: every probability is between 0 and 1 inclusive (0 ≤ P(x) ≤ 1), and all probabilities add to exactly 1 (ΣP(x) = 1).
4. Formulas:
μX = Σ[x·P(x)]     σX = √( Σ[x²·P(x)] − μX² )
Mean = "multiply each value by its probability, add them up." You will let StatCrunch do both (recipe below) — but the multiply-and-add idea is what the mean IS.
MASTER STATCRUNCH RECIPE (use on Q4–Q8)
1. Type the x-values in var1 and the probabilities P(x) in var2 (one row per outcome).
2. Stat → Calculators → Custom. Set Values in: var1, Weights in: var2 → Compute!
3. The top of the window prints Mean (= μX) and Std. Dev. (= σX). Done — no formulas typed.
4. For probabilities: in the same window use the P(X ? x) box — pick =, <, ≤, >, or ≥, type the value, Enter. It shades the bars and prints the answer.
Frequencies instead of probabilities? The Weights column also accepts raw frequencies — StatCrunch rescales them automatically (see Q5). Money problems? Build the outcome table first (see Q6).
Q1 · 6.1.1 — "What is a random variable?" definition
A — a numerical measure of the outcome of a probability experiment.
Why: that's the definition (Fact 1), word for word. Its value is determined by chance.
Trap: B adds "plotted on a line in an uninterrupted fashion" → that defines a continuous RV only. C adds "a finite or countable number of values" → that defines a discrete RV only. The general definition has no such restriction — pick the plain one.
Q2 · 6.1.3 — Two requirements for a discrete probability distribution select all
ΣP(x) = 1  and  0 ≤ P(x) ≤ 1  (choices C and D)
Why: exactly Fact 3: probabilities each live between 0 and 1 inclusive, and together they must account for 100% of outcomes (sum = 1).
Trap: "ΣP(x) = 0" is nonsense (total probability is 1, not 0). "0 < P(x) < 1" is wrong because it's strict: a probability is allowed to equal 0 or 1, so the ≤ version is the correct rule.
Q3 · 6.1.5 — Discrete or continuous? classify + list values
(a) Number of people in a restaurant (capacity 100): you count people → discrete; x = 0, 1, 2, …, 100 (choice A)
Counts start at 0 and stop at the capacity 100; only whole numbers (no 2.5 people).
(b) Inches of rain in City B during April: you measure rain — 2.37 in. is possible → continuous; r ≥ 0 (choice B)
Any value in an interval; can't be negative; no fixed upper limit.
Trap: in these answer choices, interval notation like "0 ≤ x ≤ 100" (every real number between 0 and 100) is reserved for continuous variables — a discrete answer is written as the list 0, 1, 2, …, 100. Match the notation style to your discrete/continuous choice.

Q6 · 6.1.25 — Insurance expected value $290,000 policy, $360 premium, P(survive) = 0.999544
Step 1 — outcomes from the COMPANY's point of view (this is the whole trick):

Step 2 — expected value = Σ x·P(x) = 360(0.999544) + (−289,640)(0.000456) = 359.84 − 132.08 = $227.76. Shortcut: E = 360 − 290,000(0.000456) = 360 − 132.24 = 227.76 — the shortcut uses the FULL payout 290,000 because the company keeps the $360 premium either way; don't mix it with the table's net −289,640.
Step 3 — interpret = choice C: "the insurance company expects to make a profit of $227.76 on every 20-year-old female it insures for 1 year."
Trap: "maximum profit" / "minimum profit" / "1 month" are all wrong — expected value is an average per policy per year, not a max or a guarantee.
StatCrunch: var1 = 360 and −289640; var2 = 0.999544 and 0.000456 → Custom calculator → Mean = 227.76.
Q7 · 6.1.27 — Insurance standard deviation $240,000 policy, $190 premium, E = $80.56 given
Step 1 — same two-row table: survives → +$190 with 0.999544; dies → 190 − 240,000 = −$239,810 with 0.000456.
Step 2 — σ by StatCrunch (never by hand — the numbers are huge): Custom calculator → Std. Dev. = 5123.8 → σ ≈ $5124 (nearest dollar).
Step 3 — why so high? = choice C: "because the value of the payout is much larger than the value of the gain." σ measures spread — the two outcomes (+190 vs −239,810) are ~$240,000 apart, so the spread is enormous even though a payout is very unlikely.
Trap: "probability of a payout is so low/high" explains why the mean is a small profit — it does NOT explain the spread. Distance between outcomes drives σ.

EXAM PLAYBOOK — how to replicate this on ANY 6.1 problem
  • See a table of x and P(x)? → StatCrunch Custom calculator immediately: gives μ, σ, and any P(X…) with zero formulas. "Exactly a" = one row; "more than a" excludes a; "at least a" includes a.
  • Verify a distribution? → recite the 2 rules: each 0 ≤ P(x) ≤ 1, and ΣP(x) = 1 (add them up and show it). If YOU rounded the P(x)s, a sum of 0.9999 or 1.0001 still counts as 1 — that's rounding error, not an invalid distribution.
  • Given frequencies? → P(x) = freq ÷ total, round as told, then proceed as above.
  • Pick a graph? → match the tallest bar to the biggest P(x), then check each height. Peak near left with long right tail = skewed right; mirror = skewed left; ~symmetric = symmetric. Modes = number of peaks.
  • Money/insurance? → 2-row profit table from the point of view the question names (these HW ask the COMPANY's): [+premium, P(survive)] and [premium − payout, 1 − P(survive)]. If asked from the BUYER's side, signs flip. Investments: list each profit (loss = negative) with its probability. Then Custom calculator.
  • Interpretation MCQ? → the right answer always says "over MANY repetitions the AVERAGE is about μ." Kill any choice saying most / exactly / guaranteed / one trial / maximum / minimum / wrong time unit.
  • Rounding: obey the blue on-screen instruction exactly ("do not round" vs "3 decimals" vs "nearest cent/dollar").
